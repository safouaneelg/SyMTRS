# Plan: real SyMTRS training + shadow-removal benchmark

## Context
Until now, all runs of the `symtrs` repo were made on `make-dummy`. A real dataset now exists in `…\SyMTRS\Saved\DatasetCaptures` (UE 5.8 render, City Sample). It is small: 144 transforms, i.e. 96 / 24 / 24 for train / val / test. It is a preview of the planned 20,000-transform run.

Goals:
1. Really train the repo's grid.
2. Add a shadow-removal benchmark: ShadowFormer, Restormer, Uformer.
3. Optional: a shadow ⇄ no-shadow translation of the CycleGAN/pix2pix kind.
4. Port `view_dataset` into the repo.

Validated choices:
- **uv + Python 3.12** environment;
- **new symtrs task `shadow_removal`** driven as a subprocess;
- **full grid, in stages, in short runs**: few epochs, the goal is to validate each model on this smoke dataset, not to converge;
- **Sonnet 5.5** sub-agents.

On approval, this plan becomes `docs/claude/PROGRESS.md`. The BLOCKERS, IMPROVEMENTS, SUGGESTIONS and RESULTS.md files are created at the same time.

### Blocking incompatibilities between the code and the real data
| # | Problem | Where | Fix |
|---|---|---|---|
| D1 | The names carry a prefix: `rgb_day_2048_<key>`, `depth_day_512_<key>`, `seg_day_…`. `match_by_stem` therefore finds **no pair**. | `symtrs/data/io.py:16,73,80` | Extend `normalize_stem` to strip `^(rgb\|seg\|depth)_(day\|night\|noshadow)_\d+_`. Add a test. |
| D2 | pix2pix pairs by exact basename (day ≠ night). | `pytorch-CycleGAN-and-pix2pix/data/aligned_dataset.py:93`, staging `symtrs/model/domain/upstream.py:326` | The staging creates the links under the normalized key, without touching upstream. |
| D3 | The segmentation mask is gray = ID×63, over **5 classes**: background, building, green, road, car. The code expects 6 classes with the raw value = ID. | `semantic_dataset.py`, `config.py` (num_classes) | Add a `data.label_step` parameter (63), a `round(v/63)` decoding with off-grid values → 255, and `num_classes: 5`. The decision is recorded in the checkpoint and in a test. |
| D4 | Depth is in **cm**, the sky has huge values. | `exr.py:218`, `depth_scale` | `depth_scale: 0.01`. Add `data.max_depth` (e.g. 1000 m) to invalidate the sky. |
| D5 | The RGB PNGs are RGBA. | `data/io.py` | Check that reading does go through `convert("RGB")`, otherwise add it. |
| D6 | `rgb_noshadow` is unknown to any code. | `splits.py:35,65` | Add the `noshadow` role, native 2048 only (like `night`). |

### Resuming after an interruption (if the Claude session is cut)
- **Detached launcher**: the long runs start through a `scripts/run_queue.ps1` script started with `Start-Process` (independent process). They continue even if Claude is closed; only a PC shutdown stops them.
- **Idempotent queue**: `runs/queue.txt` lists the configs in order. The launcher skips any run whose `summary.json` already exists, and resumes an interrupted run from `weights/last.pt` (`train.resume`). Re-launching it is always safe.
- **State written to disk**: each start and end of a run is appended to `docs/claude/PROGRESS.md` and to `logs/queue_<date>.log`. A new Claude session re-reads these files and resumes without context.
- **Clean stop**: a `runs/STOP` file makes the launcher stop after the current run.

### Step 3 — `shadow_removal` task (Sonnet sub-agent C, after step 1)
- Clone the three repos into `third_party/{ShadowFormer,Restormer,Uformer}` at a pinned commit, noted in `third_party/PINS.md`. As for CycleGAN, any modification is a documented minimal patch.
- Input data and target: `rgb_day` (2048) → `rgb_noshadow`. The staging follows the layout expected by each repo (ISTD style `train_A`/`train_C`) with links named under the normalized key.
- **Shadow mask**: ShadowFormer needs one (`train_B`). It is derived by thresholding the luminance ratio `noshadow/day`, then a morphological opening. It is generated at staging time and cached in `<run_dir>/staging`, never in the dataset. Restormer and Uformer do not need it.
- Training on random patches of 256 to 512. Tiled 2048 inference: reuse `engine/tiling.py`.
- Common metrics computed by symtrs (a single implementation):
  - PSNR, SSIM, RMSE in LAB;
  - the same on the shadowed area and the non-shadowed area (ISTD protocol).
- Written to `summary.json`.
- Registry: `shadowformer`, `restormer`, `uformer`. Add `TASKS`, the routing branch in `trainer.py` (train and evaluate_run), a table and a rendering in `generate_grid.py`, a line in AGENTS.md §1 and in `configs/README.md`.
- Tests: the upstream parser accepts the flags passed (same model as `tests/test_domain_commands.py`), and `resolution ≠ 2048` is refused.

### Step 4 — Smoke tests (me, then sub-agents per task)
- Unreal Editor must be **closed** during all the GPU runs.
- For each config: `--dry-run`, then `--epochs 1 --limit-train-batches 4 --limit-val-batches 2` on the real dataset.
- The time per iteration is recorded to calibrate what follows.
- Order: one model per family first (unet_small, midas_small, srcnn, cyclegan, restormer), then all the models.

### Step 5 — Short validation runs on the real dataset (background, `logs/<model>_<date>.log`)
**Goal: check that each model trains, evaluates and writes `summary.json` on the real data. We are not looking for convergence.**

Budget per run, passed as CLI flags (`--epochs`, `--limit-*`, `upstream_args`) without modifying the generated configs:
- seg, depth and SR: **2 epochs**;
- CycleGAN/pix2pix: `--n_epochs 1 --n_epochs_decay 1`;
- shadow: ~**500 iterations**.

Each run then evaluates on val and on test. The full configs stay intact for the future 20k-transform dataset.

Order, from the fastest and safest to the longest:
1. **Segmentation** (24 runs)
2. **Depth** (44 runs). The relative ones use silog + align scale, the metric ones berhu + none, relying on the registry.
3. **SR** (16 runs)
4. **Shadow removal** (3 runs)
5. **Domain adaptation** (4 runs)
6. Optional: **pix2pix and CycleGAN shadow ⇄ no-shadow**, reusing the domain front-end with the `rgb_day`/`rgb_noshadow` pair. It is a config variant, not a new implementation.

For each stage:
- launch `symtrs sweep --execute --jobs 1` in the background;
- monitor the logs;
- report the results of `symtrs tables` in `RESULTS.md`, with the mention "preview dataset 144 transforms".

### Risks
- **VRAM**: Unreal open = OOM. The ViT-L models at 2048 require batch 1, AMP and tiling. DeepLab requires batch ≥ 2.
- **Blackwell sm_120**: needs torch cu128. The compiled CUDA extensions of third-party repos will not be available without nvcc. Uformer and Restormer are pure PyTorch; ShadowFormer has to be checked (no extension a priori). If needed: `pip install` of wheels or a patch.
- **Windows**: staging symlinks (Developer mode, or hardlink/copy fallback), `num_workers` with spawn, paths containing spaces (the Unreal project folder, `<UNREAL_PROJECT>`).
- **Tiny dataset** (96 images) and 2 epochs: the numbers only validate the end-to-end pipeline. They will be marked "validation run, preview dataset, 2 epochs" in `RESULTS.md` and never presented as results, in accordance with AGENTS.md.
- **Old dependencies** of the shadow repos: ShadowFormer and Uformer pin old timm/torch. We isolate them in a dedicated venv if the conflict is real.
- **Derived shadow mask**: the threshold influences ShadowFormer and the per-region metrics. Documented threshold and sensitivity test in `SUGGESTIONS.md`.
- **The dataset will change** (move to 20k transforms): everything goes through the data-root and the config, nothing is hard-coded.
- **Writing forbidden** in `<UNREAL_PROJECT>`: the staging and the caches go only into the repo's `runs/`.
